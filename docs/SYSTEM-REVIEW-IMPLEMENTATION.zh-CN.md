# 系统评审实施记录

更新日期：2026-09-10。对应 [系统评审](./SYSTEM-REVIEW.zh-CN.md)。

本记录区分「本地实现并验证」和「生产已生效」；当前没有部署、数据库迁移或历史账目重写。
原评审保留为评审时点的记录，不把建议直接改写成当前事实。

## 实施原则与顺序

1. 先修数学单位与资金路径的确定性缺陷，再补齐交易信任边界。
2. 建立数据时间戳、TTL、来源和过期降级契约。
3. 统一历史成本、收入扣留和净收益口径。
4. 为实际管理的仓位与候选池补历史采集，再改善推荐模型。
5. 最后评估治理、对冲等新功能，不将它们当作修复资金安全的前置条件。

## 第一阶段：本地已实现

### σ 与排名快照

- UP33 使用 `2 × log(sqrtPrice[t] / sqrtPrice[t-1])`，测量真实池价格的日收益率。
- Q96 和固定 decimals 比例在收益率中抵消，不直接对巨大原始价格平方。
- UP33 / GT 都只使用相隔 86400 秒的相邻观测；不把缺失日当零收益或将多日变化当单日变化。
- 重复或非法时间戳使序列不可用，至少需要 7 个有效日收益率。
- 排名快照先因数学口径升级到 v2；第二阶段又因来源新鲜度契约升级到 `modelVersion: 3`，
  不再读取旧版本或未知版本。

上线影响：旧排名暂时不可用，直到下一次排名周期成功生成 v3；推荐候选源本身不因此清空。

### 自动触发复验

- 排队计划开始执行、以及首次资金变动前，重新检查是否仍处于原触发侧。
- sampled TWAP 沿用采样均价，并检查窗口覆盖和末次采样新鲜度；不偷换成 spot。
- 区间收缩仍要求 spot 在区间内；显式管理员执行和纯手续费收取不受自动越界条件限制。
- 条件失效且没有交易尝试时，安全放弃该计划并释放预留，恢复 monitoring。
- 已经退出或发生其他资金变动的任务继续原有恢复流程，不能仅因价格回区间而取消。

### 最终报价与恢复记账

- 普通 rebalance、恢复 rebalance、hold-quote 和 collect-fees 路径在授权后重新报价并构建交易。
- 复检 tokenIn / tokenOut / amountIn 和 approvalTarget；spender 改变时停止，不发送未匹配授权的新路由。
- 检查最终报价与构建结果声明的 minOut。配置了 `maxSwapImpactBps` 且兑换属于当前池两币时，
  用新读池价计算独立参考输出，检查报价冲击及原始「冲击 + 基础滑点」的合并下限。
- 明确配置的冲击上限在该最终检查中始终有效，包括 `safeguards.enabled=false` 的配置；
  未配置上限时不凭空添加一个上限。重试放宽滑点不能突破已配置的合并预算。
- 每次发送前保存该次 quotedOut、minOut 和 route，后续循环不覆盖已保存的最终记录；
  已确认交易回放优先使用保存的 minOut，旧任务缺少该字段才使用兼容计算。
- 检查报价准备耗时；这不是签名、RPC 广播与上链之间的原子价格保证。

边界：第三币种税费转换没有当前池提供的独立参考价；聚合器内部 actions 仍作为不透明执行步骤，
不逐项理解其中每一种协议调用。系统现在验证真实 Settler、顶层资金和输出约束，但不能消除 MEV、
公开内存池风险，或把报价到上链之间变成原子过程。

### 前端 Solver 交易边界

- ERC20 输入必须通过链固定的 AllowanceHolder，并校验外层 operator、token、amount 和 target；
  原生币输入必须直接发送到 Settler，且 value 精确等于输入数量。
- 解码 Settler `execute` 的顶层滑点约束，校验 recipient、buyToken 和链上 minAmountOut；它们必须
  分别等于当前用户、输出币和新报价声明的净最小输出。
- 授权前后都要求新报价的净预期输出和链上净最小输出不低于用户确认时展示的 minimumAmountOut，
  避免授权等待期间以更差的执行底线替换用户已接受条件。
- 不维护易过期的静态 Settler 地址表。发送前从 0x 官方 Registry 查询 feature 2 的 `ownerOf`；
  仅允许当前部署或 API dwell 期间 Registry 返回的 `prev`，Registry 暂停、读取失败或地址不匹配均
  fail closed。该做法遵循 [0x Settler 官方部署发现说明](https://github.com/0xProject/0x-settler#how-do-i-find-the-most-recent-deployment)。
- 保留精确发送者绑定、完整交易 gas estimate 和回执后实际到账检查。

边界：不逐项解码 Settler `actions` 内的协议调用；安全契约依赖 Registry 认证的 Settler 在执行时
强制顶层输出约束，以及发送前模拟和发送后余额核验。报价中的 deadline 仍是服务端路由语义，
不是本地独立解码的 Settler 顶层字段。

### 质押奖励兑换

- UP→WETH 和 WETH→策略币两跳都在授权完成后重新报价，并复用普通 rebalance 的币种、数量、
  spender、minOut、报价时效和可用池价冲击检查。
- 每一跳发送前持久化最终 quotedOut、minOut 和 route；恢复回放用已保存 minOut 核验实际到账，
  旧任务仅在缺少该字段时使用兼容计算。
- 授权后的最终报价失败或不满足边界时不发送 swap，由现有恢复流程负责重试和清理授权。

### 回归中额外发现的本金归属缺陷

v3 分开执行 decrease / collect 时，原 runner 仅从 Collect 回执读取本金，得到零本金，
将退出款误记成手续费。现改为 DecreaseLiquidity 回执提供本金、Collect 回执提供实收，
并拒绝实收小于本金的异常。合并交易保持同一语义。

没有追溯修复已有生产任务的 `funds` 或历史账本；部署前应只读筛查旧的 split-mode 恢复任务，
发现异常时以链上回执核对后另行制定迁移，不能自动推算或覆盖。

## 第二阶段：本地已实现

### 价格 seed 与派生价格

- `PRICE_SEED_FRESH_MS` 默认 4 小时。只有未过期的持久化价格可进入下一轮传播；稳定币锚点作为
  本轮明确观测，使用当前时间。
- 派生价格携带来源时间，取池状态与上游价格来源的较早者；多条深度报价合并时使用保守的最早
  来源时间。重新计算不会把旧价格的 `price_updated` 偷换成当前时间。
- 过期价格不能继续生成下游价格或 TVL，也不能进入推荐。API 将当前可用值表示为 `priceUsd`，
  仅在 fresh 时返回；`lastPriceUsd`、来源和最后观测时间保留用于审计与界面提示。
- `/api/prices`、`/api/tokens`、池列表和池组 token 元数据显式提供 `fresh / stale / unavailable`
  状态及 TTL。旧版未提供状态的响应在消费者侧按不可用处理。

### hot stats 与外部滚动指标

- `MARKET_STATS_FRESH_MS` 默认 15 分钟，即三个常规 5 分钟统计周期。V4 将链上 TVL 更新时间与
  外部成交统计时间拆开为 `updated` / `stats_updated`，刷新链上状态不会让旧成交量重新变新。
- 统计周期即使拉取失败也执行过期清理；过期的 volume、txns 和外部 liquidity 置空，但保留来源
  与最后观测时间。链上独立算出的 TVL 不因外部统计过期而清空。
- hot 集合、首页/搜索排序、公共池组、推荐地址池和 V4 推荐目标只使用 fresh 统计；旧数据可展示
  为 stale，但不能继续影响排序、候选发现或策略推荐。

### GT 缓存与排名快照

- `POOL_RANK_GT_CACHE_MAX_AGE_MS` 默认 24 小时。GT 请求失败时，未超龄缓存仅允许降级生成
  `sourceStatus: stale` 的展示快照；超龄、缺失或非法缓存为 unavailable。
- v3 排名快照保存 `sourceStatus` 与 `sourceAsOf`。API 同时检查快照生成时间和来源时间；只有两者
  都 fresh 时，排名 prior 与覆盖率 seed 才能进入推荐，其余状态只用于显示并给出界面警告。
- 当前来源状态保守地覆盖整个 GT 采集周期，而非伪造逐池精度。GT 与外部统计接口没有可依赖的
  逐行源事件时间时，`sourceAsOf` 表示本地成功摄取该响应的时间，不把本地读取时间冒充链上成交
  时间，也不恢复原评审否决的“自索引成交量”。

### 推荐链路 fail closed

- 推荐快照要求市场状态及成交统计仍在 TTL 内；过旧的 worker 快照返回 503，不继续服务旧候选。
- 推荐响应带 `freshness`，执行器再次校验状态、观测时间、TTL 与未来时间异常，并只接受显式 fresh
  的 token 价格。结果缓存的失效时间不晚于底层来源失效时间。
- stale / unavailable 数据仍可进入只读状态和诊断接口，但不能授权自动推荐或自动入场。

本阶段只建立来源与过期边界，没有声称外部滚动统计是链上逐笔成交事实，也没有回填历史数据。
数据库新增列通过现有 SQLite 启动迁移创建；正式发布仍需备份、迁移后核验和真实数据源 smoke。

## 第三阶段：本地已实现

### Gas 发生时估值与历史失败关闭

- 新增 `gas_valuations`，交易成功回执产生后先持久化 tx hash、区块、gas wei 和观测时间，再尽快
  固化策略 quote token 与结算币的可执行报价。原生币/包装原生币按 1:1 精确记录。
- 价格标记按 tx hash、job、区块、观测时间、gas wei 和版本绑定；第一次成功值不可由后来的调用覆盖。
  报价或辅助写入失败不能把已经确认的链上交易改判失败。
- 账本 gas 行携带版本化价格来源。报表不再把全部历史 gas 按当前 WETH/quote 报价折算；旧行或
  中断交易缺少发生时标记时，只显示已有可核实部分，并将本金 P/L 置为不可用。
- USDG P/L 使用每笔 gas 的结算币发生时标记。日历旧行缺少日初 USDG 资产标记时也不再用当前
  token 价格估算收益率，避免后来价格变化重写历史。

边界：没有对既有生产 gas 记录做推测性回填。旧记录在非原生 quote 下可能暂时失去 P/L 展示，
这是有意的失败关闭；只有可证明的区块历史价格迁移才能恢复，不能用当前价格补齐。

### 建仓成本基线

- 原始 mint 成本基准升级为 `basisVersion: 2`，明确把开仓 gas 保存为 native wei，而不是误命名为
  quote value。旧缓存必须重新从 NFT 原始 mint 区块、回执资金流和池状态重建。
- 无策略启动快照且无法重建原始 mint 时，不再用第一次自动 `principal_exit` 作为本金；baseline、
  P/L 和收益率返回不可用，并在界面解释原因。
- 每个完成周期新增按该周期退出时价格计算的 `capitalQuoteRaw`，执行损耗 bps 用实际周期本金归一，
  不再除以整条策略的全局 baseline。

### 10% 收益保留金及托管披露

- 保留原有「总收入严格大于 1 结算美元时保留 10%」的资金行为，但不再把它描述成 tax 或平台费。
  创建卡片与启动确认明确说明：资金仍由用户执行钱包托管，不投入下一轮 LP，不转入平台金库。
- 收益保留账本元数据记录 `rateBps: 1000`、`custody: owner_wallet` 和
  `platformRevenue: false`；performance API 新增明确字段，同时保留旧 `incomeTax*` 字段作为兼容别名。
- 当前策略收益中的平台收入显式为 0。没有虚构 treasury 转账，也没有把用户钱包保留金记成平台收入。

### 推荐净收益 v4

- 推荐模型升级为 `lp-rec-v4`。24 小时成本按「首次建仓 + 预计重开次数」计费，不再把零次重开的
  新仓错误显示为零执行成本。
- 净收益扣除 10% 收益保留金、gas、兑换/冲击成本及 pool-rank coverage 推导的预期 LVR；历史路径
  CVaR 继续作为额外风险调整项，不冒充预期 LVR。
- 成本样本只接受发生时 gas 估值完整、实际周期本金可用且周期完成时间有效的周期；按池至少 5 个
  完整周期优先，否则使用协议级真实样本。没有样本时数值为 unavailable 并硬门控为观察项，
  不再使用 0.05 USD gas、10 bps 冲击、45 秒等默认数。
- 缺少有效 pool-rank prior 时无法计算预期 LVR，同样只展示观察项。界面逐项展示保留金、预期 LVR，
  并注明首次建仓成本已包含在 gas 与执行成本中。

## 第四阶段：本地已实现

### 历史采样与失败池留存

- 推荐 tick 继续以 1 分钟桶保存 30 天；API 的近 30 小时保留分钟粒度，较早 7 日按 10 分钟下采样，
  每个样本新增返回原始 `blockNumber`，价格路径可回到链上区块核验。
- 市场历史继续保存 5 分钟滚动成交量快照并按小时输出；小时行现在同时带该小时末次样本的来源、
  tick 和 active liquidity。这里的成交量仍是 GeckoTerminal / DexScreener 提供的滚动窗口观测，
  不是本地逐笔 Swap 成交事实。
- 新增持久化 `recommendation_cohort`。每轮每类最多 80 个采样目标，其中五分之一保留给最近 30 天
  曾满足门槛、但当前已经掉出 live top 集合的池；没有失败池时名额仍回填给当前候选。这样 TVL、
  成交量或排名下跌不会让失败路径恰好从历史中消失。
- 这只修复推荐采样宇宙的即时幸存者偏差；pool-rank 的外部 top-list 来源和全市场长尾缺失仍需
  自索引 Swap/费用数据解决，当前不能声称已经具备无偏全市场回测。

### 覆盖率与置信度

- 推荐模型升级为 `lp-rec-v5`。覆盖率按固定窗口内实际占用的时间桶计算，并返回窗口、覆盖秒数、
  样本数、首末观测和最大断档；不再用首末时间差把中间断采伪装成完整证据。
- 24 小时 tick 使用 5 分钟证据桶；覆盖低于 80% 或最大断档超过 30 分钟时硬门控为观察项。
  7 日风险路径使用 30 分钟桶，覆盖低于 70% 或最大断档超过 6 小时也硬门控；单个 24 小时压力
  路径必须至少覆盖 75% 且断档不超过 1 小时，否则不参与尾部统计。7 日市场历史使用 1 小时桶，
  覆盖低于 50% 或最大断档超过 12 小时同样只作观察；walk-forward 验证要求更严格的 70% 覆盖和
  最长 6 小时断档。市场与风险路径共同约束置信度成熟度；刚开始采样的池即使当前数据完整，也
  不会立刻获得高置信。

### 手续费、IL、LVR 与流动性语义

- 窄带手续费先乘历史路径的「在区间时间比例」，再扣实测重开耗时；界面与 API 明确称其为
  `modeledVolumeInRangeUsd` 代理，不称为实测区间成交量。当前上游没有 swap-level volume-at-tick，
  所以 `volumeDistribution` 显式为 `unavailable` 并持续警告；不根据滚动窗口差分伪造逐笔成交。
- 手续费份额优先使用最近 24 小时 active liquidity 中位数，并与当前 active liquidity 取较保守的
  较大值，避免当前 tick 短暂流动性低谷放大份额。active liquidity 只是当前价格处的 L，不是跨 tick
  深度；`tickLiquidityDistribution` 因未保存历史 initialized-tick 分布而显式为 `unavailable`。
- pool-rank coverage 推导的期望 LVR 继续直接从净收益扣除；历史路径压力拆成「LP 相对 HODL 的 IL
  尾部均值」和「LP 库存价值相对路径起点的回撤尾部均值」。两者不再合并命名为未经校准的 CVaR95，
  风险调整取两种压力中较差者。
- 推荐页移除跨手续费/奖励模式混排的全局首选；各模式独立展示。卡片主值改为风险调整后 24H，
  未做路径压力调整但已扣 LVR/成本的净值降为次级信息，并展开显示两类路径压力、成交量代理、
  三种历史覆盖率及流动性依据。
